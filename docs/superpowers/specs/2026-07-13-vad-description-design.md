# VAD方式説明の改善

## 目的

設定画面で、利用者が内部の音声処理を知らなくても、精度・速度・料金のどれを優先するかでVAD方式を選べるようにする。

## 日本語の表示文言

説明の導入文を次の内容へ変更する。

> 用途に合わせて無音検出方式を選択します。

3方式を常に比較できるリストとして表示する。

- 処理なし：精度優先。小さな声や短い発話を含め、音声全体を処理します。
- サーバー：高速で、端末の負荷を抑えられます。
- ローカル：無音が多い音声では、料金を削減できる可能性があります。小さな声や短い発話が欠け、精度が下がる可能性があります。

英語、中国語、韓国語も同じ意味になるよう更新する。

## UI構造

- モデル比較と同様に、プラグイン固有クラスを持つ構造化リストで3方式を表示する。
- 短い要約行は廃止し、上記の説明を省略せず表示する。
- ローカルVADを選択した際の `fvad.wasm` 未配置案内とファイル選択UIは維持する。
- ローカルVADが利用可能な場合に表示している料金説明は、比較リストと重複するため廃止する。

## 動作上の制約

- 初期値は現在どおり「サーバー」とする。
- 既存ユーザーの保存済み設定を変更しない。
- サーバー直接送信、ローカルVAD、処理なしの音声処理ロジックは変更しない。
- APIモデル、チャンク条件、料金計算、ネットワーク形式は変更しない。

## 検証

- 3方式が構造化リストで表示されることをDOM回帰テストで確認する。
- 4言語の説明が期待値と一致することを確認する。
- 初期値が「サーバー」のまま維持されることを既存テストまたは追加テストで確認する。
- ローカルVADのWASM未配置案内が維持されることを確認する。
- lint、build、全テスト、生成物lintを実行する。
- Obsidianプラグイン配置先を差し替え、ビルド結果との一致を確認する。

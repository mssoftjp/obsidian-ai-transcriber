# 0.11.1 → 0.11.3 regression audit

Comparison: `63d141a` (0.11.1) → `f7ba011` (0.11.3), plus the local duration fix. Reviewed on 2026-09-10 JST.

## Confirmed regression, fixed locally

**Duration disappeared for media above 16 MiB.** In 0.11.2, `APITranscriptionModal.createTimeRangeControls` gained a waveform memory guard inside the same block that discovers duration. The guard threw before reading/decoding the file, so the catch displayed Unknown and left the end time empty. It was inherited unchanged by 0.11.3. The limit is file size, not minutes.

The identical synthetic 17 MiB MP4 passed against the 0.11.1 modal and failed against 0.11.3. The fix reads metadata through `Vault.getResourcePath` independently of the optional waveform. Small files retain the original audio-decode fallback. Closing the modal cancels the metadata request; errors and invalid/infinite durations have a timeout and release the media resource. A duration above the existing processing limit is displayed without allocating full PCM for a preview.

## Compatibility risks fixed locally

1. **Legacy temporary-folder collisions:** External import now preserves unmarked folders, files and invalid markers and chooses `ai-transcriber-temp-managed` (then numbered alternatives) when the original path is occupied. Existing marked roots are reused. Cleanup discovers only matching top-level roots, requires ownership markers, and can recover alternate-root sessions after restart. A bare session ID matching multiple roots does not trigger deletion; cleanup by file identifies its exact root. Six integration tests cover import, restart cleanup, collisions, unknown-data preservation, copy failure and ambiguous IDs.

2. **Rate-limit recovery:** Both transcription clients now retry temporary HTTP 429 responses at most twice, with at most 60 seconds of automatic waiting per call. `Retry-After` seconds and HTTP dates are honored; otherwise exponential backoff with jitter applies. The same client carries the cooldown into subsequent chunks, including after retry exhaustion. A server delay exceeding the remaining budget surfaces the error rather than resending early. Quota/billing errors and unknown explicit error codes are not retried. HTTP 408/5xx, transport failures and local timeouts remain non-retryable for transcription because processing status is uncertain. No outer strategy retry was restored. Tests cover recovery, both header forms, limits, later chunks, cancellation and non-retryable outcomes.

The original risks were identified from the release diff; this does not imply that the user's vault or API session encountered them. These changes are local and unpublished. The retry policy follows [OpenAI's rate-limit guidance](https://help.openai.com/en/articles/5955604-how-can-i-solve-429-too-many-requests-errors).

## Other changed paths checked

- Original-file fallback is restricted to eligible formats/size and no time range. New controller tests verify a range, cancellation or memory error never causes full-file upload; unsupported WMA/MOV/MKV are not directly uploaded.
- VAD-produced WAV is labeled as WAV, and a selected range is not applied twice. This is covered at the controller boundary and by real decoding tests for both routes.
- WMA embedding uses the generated worker and WASM in the browser tests; WMA v1/v2 decode and selected ranges are checked in both production decoder paths.
- Multi-channel downmix, WAV chunk parsing and encoded/decoded budgets are covered by the existing suites. The 128 MiB / two-hour processing budget already existed in 0.11.1; the modal's 16 MiB guard was the newly introduced duration regression.
- Resource disposal now uses the public cleanup contract; VAD cleanup failures are isolated. Modal close invalidates pending UI loads. Temporary-file cleanup requires ownership markers and preserves unknown files.
- Title API and CSS changes: removed `api-transcription-*` selectors have no references in current TypeScript. Actual modal classes use `ai-transcriber-*`. No file-save or API-key storage implementation was changed by these commits.

## Validation and limits

See `docs/testing/media-duration-regression.md` for repeatable commands. Unit/controller tests use mocked external I/O; media tests use actual Chromium decoding with a small Obsidian host shim. Native Obsidian 1.13.7 on macOS was also checked with the built plugin in an isolated profile and disposable vault: a 17 MiB MP4 showed 0:03, MOV showed 0:03, the 13-minute MP4 showed 13:00, and the over-two-hour MP4 showed 2:00:03. The registered transcription command opened the real modal; enabling range selection populated and enabled the matching end-time fields. The dialogs were cancelled and the test app was closed. No paid end-to-end transcription or Windows native Obsidian run was performed during this audit.

Deleted 0.11.1/0.11.2 GitHub releases were not recreated. The duration fix and added checks have not been published as a new release.

Validation before the compatibility fixes: 321 tests / 64 suites, 22 real-media browser tests, zero dependency audit findings and four native Obsidian modal checks. See the final compatibility validation below for the updated build.

Final compatibility validation: `npm run check:community` passed (345 tests / 65 suites), including both production client constructors and concurrent cooldown extension; `npm run test:media` passed all 22 real-media cases. No paid API request was sent. The native Obsidian checks above validate the earlier duration build; the compatibility fixes were validated with the boundary tests and complete quality gate.
